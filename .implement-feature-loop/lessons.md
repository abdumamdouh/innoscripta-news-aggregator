# Lessons — implement-feature-loop

Dated bullets on gate failures/retries and the fix. Update in place, don't duplicate.

- 2026-08-08: Item 1 (App shell + design system) stalled at the e2e gate — `mcp__playwright-chrome__browser_navigate` to `http://localhost:3100` failed with `ws://localhost:9222/devtools/browser 403 Forbidden`, retried once, same result. The mandated browser MCP needs a Chrome instance already reachable on the devtools port; nothing in the loop starts/attaches one, so any environment where that port isn't pre-opened will block every e2e gate the same way, regardless of the item under test. The dev server itself came up fine (`npm run dev -- --port 3100 --strictPort`, confirmed serving via Vite log). Static review + code review + acceptance all passed on inspection alone. Fix for next run: verify the playwright-chrome devtools port is reachable _before_ starting the loop (or switch the mandated browser MCP), since a per-item retry cannot fix an environment-level connection problem — don't burn iteration budget retrying browser_navigate again for the same root cause. Outcome: item 1 was accepted with `needs human review` rather than blocked forever — a human confirmed the behaviour manually in a browser and the item was marked `done` on that basis; every later item (2 onward) hit real, reachable e2e runs in this run's log, so the port issue did not recur, but it remains a known first-iteration environment gap to check for up front.
- 2026-08-08: Item 3 (Four live adapters + two stubs) passed static review and code review but failed the **acceptance** gate on iteration 1 (`static:pass review:pass e2e:pass acceptance:fail`) and had to be requeued; it only reached `done` on iteration 3. Root cause: the adapter mapping tests were written against thin/hand-trimmed fixtures that didn't exercise enough of each provider's real field shapes (NewsAPI/NYT fixtures especially), so the acceptance bar in GOAL.md item 3 — "mapping correctness is the whole point of this item, test it properly," every canonical field asserted per adapter, homogeneity across all four — wasn't actually met even though the tests that existed were green. Fix: `test(sources): expand adapter test fixtures and e2e coverage` (commit 188ce86) refreshed the NewsAPI/NYT fixtures with fuller real-shaped payloads and broadened `adapters.test.ts` + `e2e/sources.spec.ts` to cover the field-by-field acceptance checklist, which then passed. Lesson for next run: for mapping/adapter-shaped items, treat "acceptance" as checking the fixture's _coverage_ against the spec's explicit field list, not just that some test exists and passes against whatever fixture was captured first — a too-thin fixture can make review/static/e2e all green while acceptance still correctly fails.
